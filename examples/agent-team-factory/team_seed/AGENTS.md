# 项目规则

- 这是模型网关的独立开发实验仓。功能目标以实验台中真实用户提交的需求和补充为准，不启动其他仓库的旧流水线。
- 默认技术方向为 Go 后端、React/TypeScript 前端；具体方案由团队依据真实需求明确。按业务职责组织模块，避免将所有逻辑堆进单个包。
- 需求、设计、接口约定和验证报告放在 `docs/`，按主题建立清楚的目录和索引，随版本演进；必要时在本文件引用。
- 采用直接的业务命名、明确的错误处理和可测试的模块边界；未经用户要求，不增加旧格式兼容、静默转换或猜测式降级。
- 开发和测试通过项目实际入口执行，命令、版本、结果、未验范围如实交接。不编造产物或用户操作，不为通过修改业务断言。
- 原始日志、截图、临时数据库、依赖缓存与运行副本放入ignored目录；凭据不进源码和文档，不访问未授权的真实服务。
- Worker不自行git commit/push/merge/checkout/switch，不创建Issue/PR或部署。由Leader通过实验台工具接受候选；不修改其他任务工作区或共享运行库。
