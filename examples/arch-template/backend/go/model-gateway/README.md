# Go 模型网关

本场景面向模型请求准入、路由、上游调用、普通响应和 SSE。按请求生命周期、策略算法和运行状态组织代码，管理配置可由现有系统提供，不强制同时采用 SaaS 后端模板或某个前端。

可运行样板、规则和行为测试位于 [template](template/AGENTS.md)。先读 [Go 共用要求](../README.md)，以及[通用原则](../../../principles.md)和[工程校验与验收](../../../verification.md)。

## 代码与职责

```text
internal/
  gateway/                      请求流程、状态、取消和完成协调
  routing/                      权重、延迟、冷却及探索
  httpapi/                      模型 API 的协议适配
  infrastructure/upstream/      上游网络与协议实现
```

- gateway 协调准入、选路、调用、输出和完成结算，通过明确接口消费授权、配置及计费能力，不复制其数据和业务规则。
- routing 对外提供选择和观测操作，内部拥有权重计数、评分样本和冷却状态；不处理 HTTP 响应或 SQL。
- 上游实现处理真实网络和协议细节，所有取消、超时与错误事实返回请求流程；不能在底层隐藏重试和供应商切换。
- 请求流程可由职责明确的函数组成，不为了模板增加一套通用流程引擎，也不强迫路由算法形成业务实体及完整四层。

## 执行约束

```text
接收请求 → 鉴权与原子准入 → 取得适用配置 → 选路
         → 实际派发 → 普通响应／流式输出 → 完成记录及结算
```

明确请求、单次上游尝试和输出提交的关系。只有允许的提交前错误可以切换上游；输出已提交或请求已取消后禁止重放。实际派发前的权限、启停和配置版本复核，与管理变更保持正确的并发关系；锁和事务不跨网络等待。

候选快照、运行状态、派发与完成观测分别管理。迟到或旧配置结果不能污染当前评分和健康。未知用量保持未知，不能按零结算或把受控上游当成真实供应商。

## 校验与组合

| 要求 | 校验方式 |
| --- | --- |
| 路由策略不依赖 HTTP、SQL 或管理页面；调用方不访问路由内部状态 | Go 事实分析和统一架构规则判定，验证合规与违规样本 |
| 策略、时间窗口、冷却和观测顺序正确 | 受控时钟、明确并发屏障和规则测试 |
| 派发、重试、取消和输出提交正确 | 真实 HTTP／SSE、超时、断流及并发测试 |
| 准入、日志和结算正确 | 与项目选定的授权、配置和计费实现进行集成验证 |

Go 分析接入与基础质量按 [Go 共用要求](../README.md)维护，业务依赖约束由本场景提供，采用统一架构声明及判定。

需要身份、配置及计费管理时，可以采用 [SaaS 场景](../saas/README.md)，也可以连接现有实现。具体接口、事务衔接和联合验收由目标项目明确。
