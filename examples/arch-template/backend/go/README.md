# Go 后端

Go 场景共用本页的语言和工具链要求，业务组织规则分别归各场景。可以选择 [SaaS 业务管理](saas/README.md)、[模型网关](model-gateway/README.md)，或在同一项目中组合；不要求采用指定前端或 Go 服务框架。

## 共同工程要求

- 入口负责配置、依赖组装和生命周期；包名、导出操作及错误应表达明确职责。
- 模块定义自己需要的接口，外部实现依赖接口所在包。必须遵守所选场景的 Go 包结构；SaaS 的 application/domain 使用独立包，不能把同包文件划分称为强制隔离。
- 使用项目固定的 Go 工具链、模块及工具版本。构建、测试和检查应能在新 clone 与 CI 中独立执行。
- 基础入口覆盖 gofmt、go vet、模块完整性、实际构建及适用的 race 测试；真实网络和存储行为由集成测试验证。

## 架构分析接入候选

项目架构约束由[统一跨语言架构校验](../../verification.md#跨语言架构校验)承担。Go 接入负责提供包、导入及源码位置等真实事实；当前通过官方 go/parser 提取源码位置和导入，使用统一 Python 引擎，不另外建立 Go 专有规则体系。

[Arch-Go](https://github.com/arch-go/arch-go)及 [go-arch-lint](https://github.com/fe3dback/go-arch-lint)保留为能力对照或接入候选；需要先验证能否提供所需事实及其限制，不能默认串联其命令就完成统一校验。固定版本，验证规则覆盖、合规与违规样本、失败定位及退出码。缺配置、解析失败和未覆盖的包不能默认为通过。当前实现使用自带官方解析器适配，不依赖这些候选工具；已完成的本地验证见 [验证记录](../../validation.md)，外部 CI 另行实跑。

工具自身及项目联合验收要求见[工程校验与验收](../../verification.md)。

## 使用样板

独立选择 SaaS 或模型网关，使用根目录 scaffold.py 导出。项目根 setup.py/verify.py 提供锁定依赖及完整入口。直接运行原始 template 时，按其 docs 中命令验证，再从本目录的 tool/archcheck.py 指定 --root 执行架构检查。不要把本地架构样例检查称作产品验收。
