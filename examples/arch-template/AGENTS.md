# Architecture Template Index

本目录维护供人类和 Agent 使用的架构规范、场景样板及工程校验方案。前端和后端独立选择，项目按需要组合。实际交付与支持范围以 [README](README.md) 和 [工具说明](tool/README.md) 为准。

## 选择与阅读

1. 阅读[通用原则](principles.md)，理解模块、职责、依赖及规范归档要求。
2. 根据任务选择前端或后端，再按语言／技术栈和场景读取对应说明；无需读取或安装所有模板。
3. 阅读[工程校验与验收](verification.md)，理解规则检查、模型架构评审与证据复核，以及类型、构建和行为测试各自的责任。确定规则与模型发现分别报告，不能互相替代。
4. 组合多个模板时，明确接口、身份、数据和事务归属，再确定项目构建与联合验收入口。

| 类型 | 语言／技术栈 | 场景 | 入口 |
| --- | --- | --- | --- |
| 后端 | Go | SaaS 业务管理：身份、权限、配置、配额与账务 | [backend/go/saas](backend/go/saas/README.md) |
| 后端 | Go | 模型网关：请求生命周期、路由、上游调用与流式输出 | [backend/go/model-gateway](backend/go/model-gateway/README.md) |
| 前端 | Vue | 管理控制台：业务页面、交互状态、接口及可访问性 | [frontend/vue/admin-console](frontend/vue/admin-console/README.md) |

选择任一 Go 场景前，读取 [Go 共用要求](backend/go/README.md)。语言分析接入按语言维护；场景规则采用统一架构声明和判定，不为每个组合维护另一套架构检查实现。

本目录只收录可复用原则、场景规范和校验能力。具体项目的模板选择、迁移计划、源码基线和执行证据归项目文档或交付评估记录；不能把一个验证仓库固定为模板分类。

## 修改要求

- 共享原则和通用校验要求维护在本目录根；语言、技术栈和场景规则维护在对应场景目录。
- 场景说明应讲清适用条件、代码组织、职责与依赖、典型操作、校验及限制。代码样例、工具配置与测试交付时和对应说明放在一起。
- 前端不绑定后端语言或框架；后端不要求采用某个前端。项目按需引用独立模板，不复制维护第二份规则或源码；通用组合形式尚未定型，不预先建立组合目录或配置体系。
- 使用业务名称与最小必要设计。新层、接口、共享模块或配置必须承担当前存在的责任；不能为统一目录强迫所有场景采用四层。
- 检查工具先固定版本，验证合规和违规样本，再接入目标项目与 CI。安装成功、文档完成、工具通过和真实产品验收分别报告。
- 跨语言校验与模型架构评审属于独立工具能力，先评估可复用实现。语言不支持、分析不完整及缺少事实必须明确报告；确定规则不能被模型意见覆盖，语义问题也不能因依赖规则通过而忽略。
- 模型评估模块职责、内聚耦合、分层和抽象时，附具体代码、业务依据及影响，核对重要发现；不能凭文件长度或目录名称判定优劣。模型发现与确定规则违规分别表述，接入项目既有审查和返工门槛。
- 目标项目应能独立构建和验证，不依赖平台开发目录、本机私有状态或协调者逐次补脚本。

## 实际入口

- 用 scaffold.py 将选中的后端和前端导出到新目录；不要手工复制多份工具或覆盖现有工程。
- 项目执行 setup.py 安装锁定依赖、verify.py 验证；规范与场景文档通过项目根 AGENTS.md 引用。
- 工具 check/bundle/review/validate-review 的协议见 tool/README.md。源码或规范变化后必须重做对应检查。
- 本轮工具与模板验证见 validation.md；目标仓迁移与产品 QA 分开执行。
