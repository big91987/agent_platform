# SaaS / MaaS / UI 验收范围

依据本任务已确认的 PRD、AC、架构和用户旅程制定计划；以下是查漏框架，不是产品规格。对不适用项说明依据；缺少规则或必跑项不能记为通过。沿用挂载 QA Skill 的计划、证据、缺陷分级和报告契约，禁止修改产品实现来使测试通过。

## 计划先于执行

将每项承诺映射到角色、租户、起始状态、操作、可观察结果和最终事实。每个核心能力分别覆盖正常、非零阈值及边界、隔离、并发、失败恢复。独立计划评审节点依据文档复核并交接 READY 后，QA 才执行该版计划。执行中实质改变范围或断言，先回计划节点重新评审。报告区分计划复核、实际执行和结果复核，不能以自己写了计划代替独立验收。

## SaaS

- 从首次使用开始验证管理员、普通成员及只读角色；覆盖用户/成员添加、授权变更、撤销与再次访问。
- 对照租户、项目、成员、资源和 Key 的权限边界；跨租户读取、写入、猜测标识和旧会话不得越权。记录浏览器和 API 的独立结果。
- 覆盖空列表、首次创建、编辑、禁用、删除以及重复提交、旧数据晚到和失败后的纠正；必须核最终状态而不是仅看成功提示。

## MaaS

- 连续验证渠道/Provider 配置、来源核验、模型关联与授权、创建 Key、普通及 SSE 调用、同一请求日志/用量/费用核对。
- 次数配额、RPM、TPM、并发上限和金额预算是独立约束，逐项设定实际非零值；覆盖阈值前/等于阈值/超限、拒绝原因、窗口或配额恢复，并核不同 Key/租户的隔离。
- 并发请求需要核在途预留、完成结算、异常释放；流式取消、超时、上游限流或不可达后不得漏记、重复记账或永久占用额度。具体计费规则以本任务文档为准。
- 按声明支持的模型与接口分别验证。真实 Provider、受控上游和离线夹具分别报告；无凭据、能力不支持或环境不可达记 Blocked/Not Run，不能静默换模型或伪造联调结果。
- 外部调用遵守当前任务预算和凭据范围；只引用私有凭据，报告及截图不得泄露完整密钥。语音素材和外部付费能力依实际授权执行。

## UI

- 同一用户、作用域和浏览器会话连续完成承诺的旅程，不能用后台 API/SQL 代替中间页面操作。夹具准备和清理须单列。
- 检查桌面与窄屏下的布局、长文本/标识、表单错误、加载与禁用、键盘焦点和可访问名称；截图用于支持实际行为证据，不能代替功能断言。
- 对异步保存、切换作用域、相反操作、迟到响应及失败重试，等待本次操作对应的可观察状态，不用固定 sleep 或反复重试直到绿。
- 缺陷必须在原发现层复验。区分宿主 E2E、QA 独立实操、代码/材料审查和正式部署页面验证；任何工具限制不得包装为产品通过。

## 交付

交付同版完整报告、覆盖矩阵、缺陷复现及脱敏证据、可查看的结果看板，并明确未验项和 Go/No-Go 依据。报告文件交给正式发布节点，不自行用个人身份发评论、合并或部署。界面报告产物完成不改变产品验收结论。
