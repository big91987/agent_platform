## 实际闭环

- 用独立调用凭据通过通用 Webhook 创建会话；同一请求重复投递返回原记录，改动内容仍用同一标识返回 409。
- 第一轮记住“松果-739”和中文说明；第二轮从网页继续，生成 `report.md` 与 360×180 `preview.png`；第三轮回到 API，正确使用前两轮信息。
- 三轮 `thread.started` 均为同一个原生 thread，进展、最终回复和工具过程均持久保存。实际 API 下载的 PNG 头部与尺寸正确，文本包含正确项目代号；缺失文件返回 404。
- 两个调用来源的同名用户创建四个独立会话，回复包含各自代号；跨来源查询／续接及跨用户查询返回 403。
- 正式网页完成配置保存、原生检查和真实试运行。错误的管理选项、缺失 Skill、不可用目录及空 Webhook 输入均得到明确错误。
- 真正执行 Python 睡眠时停止：整个本机执行终止，第二条输入保持 queued，延迟文件未生成；明确继续后仍记得原代号，仅处理未执行的第二条输入。
- 真正执行中 SIGKILL 平台：重启核验并清理遗留进程，原运行输入标记 failed，排队消息不自动重放；明确继续后原生上下文恢复，延迟文件未生成。
- 独立原生测试实际使用选定 Skill 的 reference 标记、执行配置的原生 Stop Hook，并在下一轮 resume 记住原代号。未将 Skill 正文放入配置或每轮输入。

原始本地证据保存在忽略目录：`.data/native-validation.log`、`.data/integration-evidence.json`、`.data/three-turn-evidence.json`、`.data/stop-evidence.json`、`.data/restart-evidence.json`、`.data/configuration-evidence.json` 与正式 SQLite／会话目录。它们包含本机运行信息，不提交到共享源代码。

## 工程验证与评审

`./scripts/verify.sh` 执行 gofmt、前端语法和去重行为检查、go vet、Go 全集 race 测试与构建，全部通过。Go 用少量真实行为测试覆盖授权、事务、快照、队列、停止、崩溃、脱敏、路径边界和原生恢复；原生模型调用单独 opt-in，避免常规测试每次调用模型。

macOS race 链接器产生一条 LC_DYSYMTAB 警告；测试进程正常成功，非测试失败。

独立只读评审发现并修复四项实际缺陷：日志管道导致停止挂起、崩溃后旧进程存活、完成状态与取消句柄移除不原子、网页重试生成新的请求标识。前两项有评审者提供的可复现失败用例，现通过；后两项分别以同一调度锁修复和请求生命周期行为检查验证。另修复初始准备失败残留、已知原生凭据导出和异常流竞态。

## 完成边界

这是本机实验版验收，不是生产多租户认证。当前只有 Codex 和通用 Webhook；未承诺 Claude Code/DSH、钉钉/企微专用接入、远程调度、共享记忆或 Graph。网页当前按原文显示消息，完整 Markdown 富文本属于后续体验打磨。身份不明的残留进程组将阻止启动，需本机操作者核对，避免自动杀错进程。
