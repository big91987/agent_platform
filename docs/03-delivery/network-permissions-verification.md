# 联网配置与原生提权验证

2026-10-04：实现 Agent 的 `network_access` 与 `allow_elevation` 配置，以及管理员对 Codex 原生命令、文件操作、权限申请的审批。复用现有审批持久化和网页交互，不加入 Pipeline 业务逻辑。

## 已验证

- `scripts/verify.sh` 全部通过：网页、浏览器连接、Python SDK、GitHub 示例、部署控制器、Go vet / race / build。
- 单会话权限接口：只更新指定会话；原 Agent 默认值与其他新旧会话均不变。用于已授权任务恢复时限定影响范围。
- 权限专项回归：普通会话所有者不能批准原生提权；仅管理员可更新已有会话权限；执行中拒绝更新；只读会话不能通过提权获得写权限。
- 真实 Codex：预先允许联网时访问临时 HTTP 服务成功；同一原生 Session 恢复后关闭预授权、开启申请审批，收到真实原生命令审批；批准后访问成功；下一轮拒绝后服务未收到请求。临时服务收到的请求数分别为 1、2、2。
- 真实网页与真实后台：管理员登录隔离平台，配置申请审批，从网页发起仅执行 `pwd` 的验收；批准后命令完成，同一会话第二次申请被拒绝，Agent 停止且没有重试；会话信息侧栏应用当前权限成功，原会话保留。
- 停止和重启取消待审批、重复审批拒绝、跨会话隔离沿用现有审批回归。

## 边界

- 真实执行验证覆盖原生命令提权；文件与权限配置请求的响应协议、单轮 scope 和只读限制有单元测试覆盖，未宣称全部原生工具均完成端到端验收。
- 预授权联网不等于允许写入工作区外。批准单次命令可能让该命令在沙箱外运行，网页显示完整命令、原因和工作目录供管理员判断。
- 旧会话不静默更新权限；管理员在空闲时显式应用两项权限，下一轮通过 `turn/start` 覆盖原生权限，不重置 Session、不重放历史操作。

## GitHub Issue 提权通知

通知实现位于 `examples/github/permission_notifications.py`，macOS 安装入口为 `examples/github/install-permission-notifier.py`。平台核心保持不变；集成读取现有审批记录，根据任务注册表定位 Issue，发布请求与处理结果。每个审批 ID 的每种状态最多发布一次；本机记录与 Issue 隐藏标记共同处理重启和远端写入后本机未保存的重试。

7 项专门回归验证申请/批准、快速拒绝/取消、网页续接不同输入、重启去重、失败重试、会话故障隔离、任务变更后原审批通知、历史过滤和敏感内容过滤。原生权限批准/拒绝的真实 Codex 与网页证据见上文；通知模块使用模拟 API 状态验证，不将其宣称为真实 GitHub 自动通知全链路验收。
