## 自动验证与评审

`./scripts/verify.sh` 通过：9 项前端测试、6 项 SDK 测试、24 项接入测试，以及 Go vet、Go race 测试和构建。
独立只读代码评审复跑 24 项接入测试，最后一轮无阻断项。

重点边界：

- 交接已被接收但 HTTP 响应丢失：接收方补 Run ID，相同请求从冻结回执恢复。
- 同一管理请求重试：补充不重复，撤回不重复 dispatch；已接受重派不受目标后来修改文件影响。
- 撤回停止失败：不创建新 Run；中断后可从持久操作记录恢复。
- 停止条件保留：请求之后到达的新输入导致 409，不被重试扩大取消范围。
- 旧句柄、已失效回执、目标已推进或目标启动回执不明：拒绝误路由、误取消。
- 返回调用者自身阶段：拒绝自取消，按当前阶段正常交接；重复回调不将自身降为只读。
- 同目录上游只读管理和下游写任务可并行，两个写任务仍互斥。
- 原生只读模式保留 MCP 确认策略；撤回默认 `confirm`，没有改为自动审批。

当前不覆盖多租户安全沙箱、远程 Runner、已合并代码撤销。撤回仅改变执行与交接，保留已经产生的文件与历史。
