# 架构检查工具的治理范围核对

本次核对的是 Agent Platform 维护的通用代码与架构规范检查工具：它能否依据规范定位代码组织问题、说明依据并给出针对性的调整建议。Model Relay 只作为固定源码样本，不修改其业务代码，不执行产品验收。

## 工具实际做什么

| 能力 | 源码核对结果 | 限制 |
| --- | --- | --- |
| 确定规则 | 语言解析器提取包、导入和源码位置；统一规则检查模块依赖、禁止依赖、公开入口与循环 | 只检查声明的范围和约束；把整个后端声明为一个模块，不能约束包内的职责混合 |
| 架构语义评审 | 内置检查覆盖职责、规则归属、依赖、状态、可测试性、必要抽象和规范一致性；项目另加场景要求 | 这是模型候选判断，不是业务功能正确性或运行性能证明 |
| 证据核对 | 核对固定材料、检查项覆盖和精确唯一引用；源码漂移、缺覆盖、虚构引用与响应中断不当作通过 | 精确引用只证明原文存在，不证明推理、影响或建议正确 |
| 人类可读报告 | 原报告已有源码引用，但以技术状态、英文键和执行元数据开头，未显式呈现解析器已知的函数/类型 | 这影响报告理解；协调者的概括又漏掉原有具体引用，不能因此声称工具完全没有定位对象 |
| 编码基础检查 | 当前工具提供架构治理，不自行执行格式、类型检查和构建 | 这些继续由项目固定的格式化、lint、类型与构建工具承担，不宣称本工具覆盖全部代码规范或所有语言 |

原 DeepSeek 报告的七项标题均为架构治理问题：模块集中、分层混合、规则重复、选路与适配耦合、规范不一致、共享状态以及前端边界。协调者后来补出的配额上限和版本冲突验收不是工具发现，也不属于本次任务。旧模型的部分 validation 建议包含产品业务断言，需要与架构复查范围区分，不能把它们升级为新需求。

## 本次维护源修正

工具版本 0.4.1，JSON 协议和确定依赖规则不变。

1. 明确模型只检查业务规则的归属、重复和耦合，不判定产品计算结果、配额阈值或权限决策正确。建议须指向具体路径、包、类型或函数的职责与依赖变化，不仅给“拆模块、加层”等口号。
2. validation 要说明架构复查，已有回归仅保护原行为，不凭空添加业务验收条件；未测量的运行影响只表述为风险。代码判断要求实现证据，规范文件只能单独证明规范一致性问题。
3. 将模型报告语言明确为简体中文，保留代码标识和路径，避免仅写“用户语言”而未向模型提供用户对话的歧义。
4. Markdown 先展示独立规则结果和候选架构问题，再列位置、解析器识别的符号、依据、影响、调整和复查建议。模型文字保持原样；不能靠人工补产品设计或关键词过滤让输出看起来合格。

不修改既有产品对象、业务条件、测试断言或业务接口，也不将本轮工具修改直接写进产品运行副本。

## 验证与证据

- 50 项工具回归通过，包含真实语言解析、规则正反例、引用/覆盖、模型传输、失败传播和新报告定位。初次受限环境中的三个本地监听错误已在允许 127.0.0.1 监听的环境复验通过。
- 12 项模板导出、安装升级及工作流测试通过；报告实现随标准工具导出，不依赖当前开发工作树。
- Ruff 检查、格式检查和差异空白检查通过。

独立复审发现并复现了报告抽取引入的升级锁冲突回归：标准隔离入口在锁错误后导入报告模块失败。报告函数已收回启动脚本，新增失败回执回归通过，复审无遗留 Important/Critical 问题。

这些回归证明执行路径与协议，不单独证明模型判断质量或保证建议永不越界。[真实 DeepSeek 复验](architecture-reports/model-relay/2026-11-06-tool-audit/README.md)三轮的完整结果均已保留：一轮接受、两轮拒收，尚未验证稳定可用；历史原始报告不改写为新版本成功。
