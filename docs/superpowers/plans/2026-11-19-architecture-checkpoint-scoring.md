# Architecture Checkpoint Scoring Implementation Plan

**Goal:** 评分反映各项要求的实际达标情况，单个严重问题不再使整个维度归零。

**Architecture:** 七个维度保持不变，每维四个固定检查点。模型逐点判断并引用发现；工具核验、按点取最严重档、在维度内平均，再对七维等权平均。评分口径 2.0、工具 0.7.0；不改确定规则门禁，不保留旧评分执行分支。

**Tech Stack:** Python、现有 Go/TypeScript 事实解析器、已配置模型适配器。

**Spec:** 用户要求优化“严重偏差使整维度归零”；已授权直接实施、默认模型评测并在 MaaS 验证。本方案为本次实现选择。

## Decisions

- 固定检查点取代问题数量或文件数量计分，避免拆分问题影响得分。每点沿用符合100、轻微80、中度50、严重0；同点重复问题不累扣。
- 一个检查点严重偏差、其余三点符合，维度为75。维度0须全部适用点为0；不适用必须说明理由并排除分母，缺证据不发总分。
- 每个偏差点必须关联同维度的真实发现和源码证据；每个发现必须至少解释一个相应检查点。父项状态须与子项一致，不能遗漏、重复、伪造点或引用。
- 确定依赖规则违规只压低对应依赖检查点，违规数量和退出码独立保留；不得由高总分覆盖。
- 不把旧回执手工拆点，也不把新旧分数差说成整改效果。旧报告保留；新默认模型入口在固定 MaaS 快照重新运行，原生 JSON/Markdown 同源。
- 不修改 MaaS 产品代码、不做业务 QA、不提交或部署；不引入评分权重配置框架。

## Tasks

- [x] 编写单严重点、重复发现、不适用/未完成、规则违规和引用非法的失败回归。

- [x] inspect_project.py 展示检查点分与扣分原因；同步受控协议夹具、使用说明及版本。
- [x] 工具/模板完整回归、格式检查、标准安装升级验证。
- [x] 使用默认模型入口重新评测固定 MaaS 前后端；核对引用、结构、评分分母、原始文件及原生报告；交付新旧口径对照。

## Review Focus

- 单个发现影响多个点时，各点须说明具体影响，不能自动扩散到整维度。
- 模型将规则对应点写成符合或不适用时，确定规则仍压低该点并保持违规门禁。
- 缺点、未知点、重复点、越界/布尔引用、无发现的偏差点，均明确未完成。
- 不适用和证据不足不奖励分数；全不适用不发总分。
- 历史模型回执和旧报告不可补写字段冒充新评测。

后端第三轮首次有效；前端前四轮因覆盖/格式/重复点/引用及额外字段未完成，第五轮使用真实第四轮原件及校验错误作为明确documents上下文重新评审后完成。所有原件保留，未修补回执。前端整体输入摘要因此变化；只有生产文件及原始规范保持一致。此过程不代表独立盲评或已实现自动恢复，协议遵循的稳定性仍需改进。
