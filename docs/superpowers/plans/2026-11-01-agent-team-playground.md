# 用户驱动的 Agent Team 验证原型

用户已确认：固定 Worker 池、Leader 通过工具持续派发，基础设施仅负责队列、消息、事件唤醒、隔离与执行记录。目标仓为 `big91987/model-relay-2`；不接 Issue/PR，不替用户提交需求，不复用 Model Relay 产品或它的重型门禁。

采用 Python/SQLite 和现有原生执行/Git 隔离内核；这是可丢弃的单用户原型，不建设分布式队列或多租户平台。

- [x] 定义需求、任务、固定消费者、消息与原生轮次的持久状态；并发原子领取。
- [x] Leader 获得读取看板、创建/取消任务、消息、接受成果、完成需求工具；Worker 保持读取任务、消息、handoff 三工具。
- [x] 固定3个消费者；新需求和Worker结果唤醒Leader，Leader决定下一步，不写死开发阶段。
- [x] 提供5份可实际加载的标准Skill；原始输入、输出、工具与结果按需求可见。
- [x] 提供一句话提交、需求池、任务、消息、执行轨迹、代码和产物页面。
- [ ] 隔离基础设施回归及真实页面检查；运行环境接入新空仓，保留空需求池交用户试用。

Leader保留自己的原生会话；Worker是预先启动的固定消费者，空闲不调用模型，每个任务使用独立原生会话与worktree。发布分支和接受候选是Leader显式调用的基础设施动作，不是外层自动业务编排。测试设施使用独立临时存储；真实运行库不得预塞需求或补造Agent轨迹。

本机完整55项基础设施回归通过（真实子进程/Git/stdio/HTTP，使用隔离临时仓），Ruff与脚本语法检查通过，5份Skill结构验证通过。独立评审原三项Important已修复并复验：保留用户补充消息、异步提交不丢输入、轮询不折叠已展开轨迹。实际模型团队执行等待用户在空需求池提交，不以协议夹具冒称。
