# Agent Platform 实验版 PRD

> 状态：实验范围已确认；用户授权架构设计与连续实现（2026-10-01）。
> 日期：2026-10-01
> 本文中的“已确认”来自需求讨论；“建议默认”用于形成可审查的实验范围。

## 1. 背景与目标

现有原生 Agent 可以在命令行或桌面持续干活，但外部系统接入、后台运行、对话续接、配置复用和产物查看仍需要各自处理。之前使用 Issue 与 CI/CD 承载持续对话，暴露了交互绕、运行与会话状态难理解、环境问题不易恢复等问题。

本平台把配置好的原生 Agent 提供为可持续交互的服务：外部系统调用后取得会话标识和平台页面链接，用户可回到平台查看结果、补充信息和继续工作。

平台是通用 Agent 平台。研发流程是可配置的用途之一，不在产品中固化需求、设计、开发阶段；输出也不限定为网页。

实验成功的判据：从正式配置入口配置一个真实 Agent，通过 API 创建会话，在网页回复后再通过 API 接续同一会话；全过程能够查看真实消息、执行过程和产物，发生故障时不会悄悄丢失会话或重复执行。

## 2. 已确认边界

- 后台采用 Go；平台与执行器在同一台机器运行，没有远程执行机器需求。
- 配置可接入 Codex、Claude Code、DSH 等原生执行器，并利用其 Skill、Hook、工具与原生配置能力。
- 外部入口为 API／Webhook；会话事实源由平台维护，GitHub／GitLab 等系统保留入口和会话关联即可。
- 外部调用与平台网页接续同一会话。内部原生 Session 标识、执行进程和恢复方式不成为调用方负担。
- 首版单 Agent；Graph Workflow、多 Agent、蜂群和共享记忆策略后置。
- 首版自用，认证和部署简单；不要求 K8s、消息队列或分布式调度。
- 常用配置通过界面操作，高级能力保留原生配置入口。
- 运行中收到的新消息先保存并排队；停止是单独操作。

## 3. 实验范围与建议默认

### P0：先完成一条真实可用的闭环

1. Agent 配置、保存、可用性检查和试运行。
2. API 创建、查询和接续会话，返回可跳转的平台对话链接。
3. 网页查看与回复：即时进展、最终回复、工具过程、日志和产物。
4. 本机后台执行、不同会话隔离、排队、停止与失败后的明确恢复。
5. 平台重启后仍能找到会话、消息、配置引用和产物；可继续的会话能够接续。
6. 入站 Webhook 接收外部事件并调用指定 Agent，返回或关联会话。

### 建议默认，需随本版范围一起审阅

- **首个真实执行器先接 Codex**，在此基础上验证统一会话接口。Claude Code／DSH 仍是平台目标，但本次实验不同时承诺三个适配器完成。
- 常用配置包括名称、执行器、模型、工作目录、指令、Skill 范围、Hook 和环境设置；不支持的原生选项明确报错。
- 平台提供管理员和调用方用户两种基本角色；每个用户有固定 User ID 和一个 API Token，网页通过用户名密码登录指定会话。组织、团队与复杂角色体系后置。
- Webhook 首轮只验证一种约定的 JSON 输入；GitHub、钉钉、企微的专用签名、事件转换与机器人回复不都纳入本次实验。
- 初始并发执行数可配置；未取得执行位置的输入保留在队列中，不向用户暴露进程分配。
- 已创建的会话继续使用创建时的 Agent 配置；配置修改默认用于新会话，避免续接时行为无提示变化。

### 当前不做

可视化工作流编辑器、多 Agent 编排、跨会话共享记忆、独立知识库、远程 Worker、复杂权限管理、自动合并代码、完整研发供应链治理。

出现单 Agent 无法完成的明确协作需求后，再评估 Graph；出现实测容量问题后，再评估调度扩展。当前不预先创建这些功能。

## 4. 使用者与责任

| 使用者 | 做什么 | 得到什么 |
|---|---|---|
| 内部操作者 | 配置 Agent、准备本机执行环境、调试、查看和处理会话 | 可调用的 Agent、运行证据和可接续的页面 |
| 外部调用系统 | 提交用户输入，保存会话标识，接收或查询结果 | 同一会话的回复、状态和平台链接 |
| 会话使用者 | 从业务系统发起请求，必要时进入平台查看、回复或停止 | 一段连续的工作，不需要理解内部进程 |

本机维护者负责执行器安装、原生登录和工作目录权限；平台检查实际可用性，不把“已安装”直接等同于“可调用”。配置错误、环境故障和 Agent 业务判断分别呈现，不能统一伪装成等待用户回复。

**访问边界：**Agent 配置授权用户。用户 API Token 和账号登录使用同一身份，只访问自己的会话；管理员可管理全部会话。固定链接没有 Token，无到期或刷新流程。

## 5. 核心对象与生命周期

| 对象 | 首次可用路径 | 后续行为与边界 |
|---|---|---|
| Agent 配置 | 操作者在界面选择本机执行器，配置并执行可用性检查／试运行 | 修改配置、再次验证、禁用新调用；禁用不删除已有会话 |
| 会话 | API／Webhook 首次输入或平台试运行创建，平台返回会话 ID 与链接 | 持久保存消息和产物关联；API 与网页均可回复；关闭后不能继续执行，历史仍可查看 |
| 消息 | 用户提交或 Agent 实际输出后保存 | 用户消息按会话顺序处理；Agent 进展与最终回复区分；失败不删除原始输入 |
| 产物 | Agent 实际生成，平台保存并关联会话 | 可查看／下载；图片可直接展示；未产生、缺失或不可访问的文件明确提示 |

执行进程是内部运行手段。同一会话可以先后由不同进程接续；终止进程不等于删除会话。持续会话也不要求进程在等待用户时一直占着执行位置。

首版不引入额外的任务、研发阶段、审批台账或运行实例作为对外必填对象。

## 6. 详细用户旅程

### US-01：从零配置一个可调用的 Agent

1. 操作者打开 Agent 页面，创建配置并命名，选择本机执行器。
2. 设置常用参数，选择允许使用的 Skill、Hook 和工具；高级选项通过原生配置入口补充。
3. 点击检查。平台报告执行器是否存在、配置能否使用、工作目录是否可访问，以及需要补齐的原生登录等条件。
4. 发起一条试运行消息。操作者看到真实输出和执行结果，不只看到“配置保存成功”。
5. 检查通过后取得调用说明与授权方式，供外部系统接入。
6. 后续可修改或禁用配置。已有会话不因配置删除／禁用而悄悄失去记录。

Skill 采用执行器原生发现与渐进加载方式；平台控制可用范围，不将所有 Skill 全文拼入每轮提示词。Hook 的能力及执行语义由具体执行器决定，界面不把不支持的选项显示为已经生效。

### US-02：外部系统创建会话并回到平台交流

1. 调用系统携带用户 API Token、Agent 标识及输入，不携带会话 ID。
2. 平台验证授权，创建会话，保存输入，返回会话 ID 和页面链接。
3. 有执行位置时开始本机执行；否则显示排队，输入仍已保存。
4. Agent 实际输出进展时，平台及时展示；最终回复到达后单独呈现。
5. 用户打开固定平台链接；未登录时用账号密码登录，随后自动回到同一会话，看到历史、进展、文件和当前情况。
6. Agent 需要澄清或人工操作时，说明需要用户做什么。平台不替所有 Agent 加固定审批流程。
7. 用户在页面回复，输入回到这段会话；调用系统随后带同一会话 ID 提交下一条输入，仍能接续之前的交流。

### US-03：多个来源和用户同时调用

1. 管理员为平台用户配置 Agent 授权；调用系统使用对应用户的 API Token 发起请求。
2. 首次请求创建独立会话。相同用户名、同一个 Agent 或复用执行进程均不能导致历史混用。
3. 平台按配置的本机执行上限处理输入，其余排队。
4. 查询一个会话时只返回有权访问的记录；其他用户不能仅凭猜到 ID 接续它；同一用户通过不同入口仍能接续自己的会话。

### US-04：运行中补充消息与停止

1. Agent 运行时，用户仍可提交消息，页面立即显示该消息已保存、等待处理。
2. 当前轮结束后，按顺序处理新输入；提交消息本身不自动打断执行。
3. 用户点击停止，平台请求停止当前执行并报告实际结果；已经完成的外部操作不会被宣称撤销。
4. **建议默认：**停止后未执行的消息保留但不自动启动；用户明确继续后再处理。

### US-05：异常与重启后接续

1. 执行器退出、原生服务失败或本机环境不足时，保存已完成输出，显示具体失败位置及可采取的操作。
2. 平台重启后，会话历史、消息与产物仍可查到；正在执行的工作不能仍被永久显示为运行中。
3. 用户选择继续时，恢复原生会话所需记录和工作目录；恢复不可用时明确告知原因。
4. 不偷偷换成全新原生会话，不自动重放结果未知的操作，不要求用户重新输入全部历史来掩盖数据丢失。

## 7. 对外调用约定

以下是产品语义，字段名称为建议，正式接口规格在架构阶段确定。

| 信息 | 调用方责任 | 平台责任 |
|---|---|---|
| 调用凭据 | 用户 API Token 证明调用身份 | 识别用户并核对 Agent 授权 |
| `agent_id` | 指定要使用的 Agent | 选择配置，检查是否可用 |
| `user_id` | 可省略；传入必须与 Token 对应用户一致 | 从 Token 识别平台用户，不凭请求字符串更换身份 |
| `conversation_id` | 首次可不传，接续时传平台返回的值 | 创建、查询、校验归属并恢复同一会话 |
| 输入内容／附件引用 | 提交消息和所需资料 | 保存输入，报告不可访问的资料 |
| 会话页面链接 | 保存或展示给用户 | 打开同一会话，执行访问控制 |

首版需要：创建并提交输入、向已有会话提交输入、查询会话及当前运行情况、读取消息与产物、停止当前执行。流式输出供页面展示；调用方可查询已保存结果。

查询“是否正在执行”不等于预约或锁定会话。能否接收下一条消息由提交入口判断；运行中允许保存排队消息。

**建议默认：**调用方可携带稳定请求标识去重。同一用户重复提交同一请求，返回原来的接收结果，不重复创建会话或执行。网络响应丢失不应迫使调用方猜测是否可以安全重试。

## 8. 页面范围与交互要求

| 页面 | 必须完成的操作 |
|---|---|
| Agent 列表／配置详情 | 创建、修改、检查、试运行、禁用；查看原生能力是否受支持；获取调用说明 |
| 会话列表 | 按 Agent、来源和当前情况查找会话，打开对应对话 |
| 会话详情 | 查看历史、即时进展、最终回复和排队消息；回复、停止、继续；预览／下载产物；展开执行日志 |

- 用户对话按实际时间顺序展示；不以一条覆盖旧内容的总结代替历史。
- 主区呈现 Agent 的真实回复；工具调用、技术日志与原始事件可折叠查看，并标明来源。
- 排队、执行、等待用户、失败及停止必须可辨认。只有 Agent 明确需要用户输入时，才显示等待用户及所需操作。
- 图片／截图在对话内有明显入口并可直接查看；其他文件按可预览类型展示，均提供下载。
- 不要求用户理解 Schema、原生 Session ID、进程编号或内部调度状态。

## 9. 质量与运行边界

- 会话、输入、已收到输出和产物关联持久化；原生上下文恢复所需文件与工作目录同样纳入持久化边界。
- 同一会话不同时执行两轮，避免原生上下文和文件互相覆盖；不同会话的运行目录与原生记录隔离。
- 配置及环境错误在调用或运行结果中可定位；未验证的能力不能显示为成功。
- 运行观察不能依赖用户到终端查文件或直接修改数据库。
- 密钥不写入消息、日志、导出的配置和产物；原生登录材料由本机受控环境提供。
- 首版不承诺强多租户安全隔离或任意不可信代码托管。本机文件及工具访问边界须在运行前可见并可配置。
- **建议默认：**首版不自动删除会话与产物；提供明确的手工清理操作，告知清理对后续接续的影响。

## 10. 验收标准

| ID | 可观察结果 | 验证方式 |
|---|---|---|
| AC-01 | 从界面配置一个真实执行器并完成试运行；错误路径能指出缺失执行器、无效配置或不可用目录 | 使用有效与无效配置实测 |
| AC-02 | 第一次 API 输入返回会话 ID 与页面链接；打开链接看到同一条输入及真实回复 | API 调用与页面核对 |
| AC-03 | 网页补充信息后，API 用同一 ID 接续；Agent 能利用此前已确认信息，历史连续 | 连续三轮真实交互 |
| AC-04 | 不同用户和两段独立会话不会混用历史；越权查询／续接被拒绝 | 四段会话交叉验证 |
| AC-05 | 超过配置执行上限时排队可见；已有会话运行中提交的消息保存并按顺序处理 | 限制执行数并提交多条输入 |
| AC-06 | Agent 输出进展时页面可见；最终回复独立展示；过程日志可展开且历史不被覆盖 | 真实长轮次执行 |
| AC-07 | 图片及非图片文件均来自真实运行，可在会话查到并下载；丢失文件明确报错 | 生成图片和文本文件后检查 |
| AC-08 | 停止有实际结果；未执行消息未丢失、未擅自启动；继续行为符合已定规则 | 运行中停止并继续 |
| AC-09 | 重启后历史和文件可查，异常执行被识别；可恢复会话接续，缺失原生记录则明确失败 | 在等待与运行两种情况下重启 |
| AC-10 | Skill 范围与原生 Hook 经实际调用验证；不支持的设置不会静默忽略 | 使用可辨认行为的配置实测 |
| AC-11 | 同一请求标识重复投递不重复创建／执行；失败信息可查询 | 重复请求与响应中断实测 |
| AC-12 | Webhook 真实投递创建或接续会话；无效身份／输入明确拒绝 | 约定事件格式的端到端实测 |

操作者执行验收并保留真实请求、消息、截图和失败证据；用户审阅核心旅程与页面体验。原型只能验证交互，不能证明 AC-01、03、09、10 的执行与恢复能力。

## 11. 依赖、风险与待审事项

依赖：本机原生执行器及有效登录、可写工作目录、可持久保存的数据空间、调用系统提供稳定用户与请求标识。

技术风险：各执行器的恢复、Hook、Skill 配置及事件输出能力可能不同；必须验证后再承诺。持久保存文本历史并不能单独保证原生会话恢复。共享本机也不等同于文件访问天然隔离。

本版采用的实验默认值（用户授权按合理架构实施）：

1. 首个实验只接 Codex，后续再接 Claude Code／DSH。
2. 外部接入先完成 API 与一种通用 Webhook 格式，专用渠道适配后置。
3. 简单登录供内部操作者使用，调用系统使用用户 Token，Agent 配置授权用户。
4. 停止保留队列且需明确继续；已有会话维持创建时配置；不自动清理记录。

详细接口格式、数据存储、原生配置映射和故障恢复实现由后续架构设计确定。当前没有指定服务拆分，也没有将 Session／Runtime 设计为独立部署服务。
