# Workflow G1 评审

日期：2026-10-05。基线：[产品需求 v1](workflows.md)。

结论：`Ready for Architecture`，按用户明确委托的推荐方案自主推进执行；此结论为代理自查，不表示用户逐条审阅过本文。用户要求“先需求、再设计、再开发；先写出来，尽量不反复确认”。

已满足：目标、角色、资产首次可用路径、价值闭环、职责边界、当前串行图范围、失败恢复、人工回退、可观察 AC 均已定义。原单 Agent 版本继续使用，新增平台编排独立演进。研发阶段属于模板，不能固化在内核。

非阻塞缺口：真实执行器交接接入、外部动作结果核验、编辑器可用性需要实现验证；均进入交付任务，尚无端到端通过结论。模型延迟和外部 API 限制按实际测量记录，不编造性能承诺。

阻塞项：目前无须用户决策的方向冲突。

带入架构：Run 内循环；显式节点完成；旧回执失效；配置快照；凭据隔离；不确定副作用不自动重放；旧运行与旧平台数据兼容；新仓库和隔离服务验证。

简化审查：保留 Workflow、Connector、Run 和节点执行事实；复用 Agent／会话／身份；不增加组织、远程执行或通用编程语言。

## 典型旅程补审（WF-13～15）

按用户明确补充的场景扩展现有 PRD：范围明确的修复可实际跳过需求／设计，信息不足必须澄清，结构变化仍进入设计，交接后人工纠正应停止旧执行再接续。此处沿用已授权方向，不追加形式审批。

简化结论：阶段判断由研发模板的 intake Agent 和合法自主边承担；通用内核不增加研发分类、第二套状态机或额外意图模型。起点可在任务中自然语言指定，必要分支准备及 Issue 关联不被绕过。验证范围由实际改动决定；运行事实与 Agent 的“已完成”声明分开核验。

沙箱缺少监听能力时，复用已配置的项目测试 Connector，不临时扩大 Agent 权限；只有宿主测试实际执行、独立 QA 核对后才能进入交付。实现与实测结论见交付验证记录，不以本评审代替验收。
