# 实验版需求评审

> 状态：Ready for Architecture（实验版，2026-10-01 用户授权进入架构与实现）
> 评审对象：`prd.md`
> 日期：2026-10-01

## 结论

已形成可审阅的实验需求草案，覆盖配置、外部调用、平台接续、执行观察和故障恢复。用户已授权合理架构与连续开发，本版采用 PRD 中的实验默认值。

## 已满足

- 产品定位是通用 Agent 平台，未固化研发阶段或网页产出。
- 平台与执行器同机本地运行；会话由平台维护，外部系统只需调用和保存会话关联。
- Agent、会话、消息、产物的来源与使用路径明确，不依赖数据库直改或临时补丁。
- API 和平台网页共用会话；运行中消息、停止、故障和重启有可观察行为。
- 页面范围与验收场景可追踪至同一条用户旅程。
- 未加入 Workflow、蜂群、远程调度或复杂组织权限。

## 待用户审阅的范围建议

| 建议 | 影响 |
|---|---|
| 首轮真实接 Codex，Claude Code／DSH 后续接入 | 缩短首次实验，但首轮不能宣称三种执行器均可用 |
| API 与一种通用 Webhook 输入先完成 | 能验证外部接活；钉钉／企微／GitHub 专用接入尚不能直接宣称完成 |
| 简单内部登录及独立调用凭据 | 首版不实现终端用户统一登录和复杂协作权限 |
| 停止后明确继续、会话配置保持稳定、手工清理 | 减少意外重放和续接变化，增加少量明确操作 |

## 带入架构的验证事项

- 用真实 Codex 验证原生上下文、工作目录和记录在平台重启后可接续。
- 验证 Skill 范围、原生 Hook 与环境配置的具体映射方式。
- 明确本机文件访问及不同会话隔离边界；不将目录分离夸大为强安全沙箱。
- 确定输入去重、执行中故障和结果未知时的恢复规则，避免重复外部副作用。
- 明确运行事件如何实时进入页面，如何持久保存并供调用方查询。

## 下一步

用户审阅并收口实验范围后，按三类页面做可点击原型：Agent 配置、会话列表、会话详情。原型使用清楚标识的演示数据，不宣称已接真实执行器；真实运行与恢复另行实施和验收。
