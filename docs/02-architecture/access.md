# 用户、Agent 授权与会话访问

## 当前约定

一个用户有一个固定 User ID、用户名密码，以及一个可选 API Token。管理员在 Agent 配置中选择授权用户。普通用户可调用获授权的 Agent，只查看和接续自己的会话；管理员可管理平台和全部会话。

API Token 绑定用户，数据库只存哈希。Token 不自动过期或轮换，管理员可在用户页面生成、重置、撤销。重置立即使旧 Token 失效；撤销 Token 不删除会话，也不取消正常网页登录。停用用户会阻止 API 和网页访问。

网页登录使用账号密码和 HttpOnly Cookie。普通用户的身份从 Token 或登录账号确定，不能通过请求中的 user_id 更换身份。管理员可管理其他用户会话。授权用户列表存于 Agent 配置（authorized_users），每次认证和 SSE 授权检查都读取最新权限；原生配置快照不冻结平台权限。

用户名与 User ID 创建后不可变；新用户默认生成 User ID。原用户的稳定 ID 在升级时保留，旧来源内重名 ID 会迁移为独立平台 ID。

## 固定会话链接

API 返回 conversation_url，例如 `<service-endpoint>/conversations/<conversation-id>`。链接没有 Token，不授予权限，也没有链接到期或刷新功能。

- 已登录：检查会话归属和 Agent 授权，打开原会话。
- 未登录：输入用户名密码，成功后自动回到链接指定的会话。
- 其他用户：拒绝访问，不因知道 conversation_id 而获得权限。

Issue 只显示固定入口、会话 ID 和登录说明。API Token 不放进 URL、Issue、日志或产物。GitHub Runner 使用配置的用户 Token；Issue 作者信息不是平台身份凭证。

## 持续执行与接续

会话、消息、事件与原生 Session 由平台保存。网页断开、登录失效或 API Token 撤销不因此删除记录或中断已经接受的任务。事件流支持游标重连；账号重新登录后继续访问原会话。新输入恢复同一原生 thread_id，不另建 Session 冒充接续。

## 升级

平台在数据库事务中迁移已有账号和会话归属，并将旧调用凭据的 Agent 范围转换为对应账号的 Agent 授权。保留用户名、密码、会话 ID、原生历史、消息、请求去重记录和文件。无法唯一确定旧账号归属时拒绝迁移，要求明确映射，不猜测。

旧来源级凭据无法证明用户身份，因此不会自动变成用户 Token；升级后为调用账号生成 Token 并更新调用系统配置。撤销原匿名临时会话访问，删除临时授权与来源凭据表。已登录的正式账号仍按当前用户权限检查。旧带 fragment 的链接打开时移除 fragment，改走正常账号登录。

## 本地登录

本地实验首次启动默认 admin/admin，可用 AGENT_PLATFORM_PASSWORD 设置初始口令。重启不覆盖已保存密码；用户页面修改账号会使该账号旧登录失效。密码采用随机盐 PBKDF2-SHA256。浏览器登录保留正常 24 小时有效期，用户无需管理链接期限。
