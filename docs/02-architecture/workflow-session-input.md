# 工作流角色指令与会话输入

状态：输入分层沿用2026-10-07修订；Agent交接按2026-10-22确认的统一handoff契约。实施与真实Pipeline验收见交付计划，不把旧版结果当作新版验收。

## 输入与执行

Agent.instructions 仅保存角色职责；Codex 映射为 developerInstructions，并原生发现工作目录内 AGENTS.md。平台不得修改该文件或再手工复制。工具通过已有注册层传递，具体任务、材料引用、交接、修正走 User Input。没有独立的节点工作说明字段。

`Workflow.context_version=2` 是新编排默认。Agent 节点不允许非空 `prompt`；角色职责放 `agent.instructions`，任务在 Run 启动时由用户/API 输入。合法交接目标、策略、完成与等待规则由既有 edges 和节点设置生成，用户无需维护占位符。人工确认节点的 `prompt` 仍表示确认内容。

`workflowNodeInstructions` 生成交接工具规则；`workflowAgentInput` 追加原任务、成功投递的用户修正、最近上游交接、最近每个 Connector 回执及回退原因。正文 Markdown，不复制全图或累计 Agent 结果。长命令输出通过日志工具读取，不把运行数据回写角色配置。

预览 API 使用当前草稿和同一工具规则生成器，v2 只返回输入示例，没有 session_prompt 字段。真实冻结输入在 Run 节点详情查看。连线和目标/策略列表使用一份 edges 数据。

兼容：缺失/0 保留最初的冻结协议；1 保留原节点 prompt 及 {{handoff}} 展开。编辑旧图仍保留旧字段，不能静默迁移丢失人工文字。正式模板拥有的图通过原 manifest 升级到2：长期阶段协作规则/验证职责配置在角色指令中，具体需求及材料仍来自入口输入和回执；外部编辑漂移拒绝覆盖。任意自建旧图需管理员先把长期职责归入角色、具体任务归入启动输入，再去掉节点 prompt 并切换版本。任何升级均不改写旧 Run 图、原生会话或消息。

## 完成与等待

Agent通过显式 `handoff(target, message, params?, artifacts?)` 提交交接。无论目标有一个、多个，或目标为结束节点，都必须填写合法target；不再提供complete_node或双模式选择。交接参数开关默认关闭，工具不提供params；开启后根据配置的handoff_schema校验params JSON对象，并向Agent提供Schema和handoff_instructions填写说明。`wait_for_input(reason, kind)` 的kind为clarification或blocked；它不完成节点，只声明为什么必须等待。自然语言回复不作为完成或澄清信号。

新节点配置 continuation_limit（0–10 次；0 关闭）与 execution_timeout_seconds（0–86400 秒；0 不启用时间限制）。正式模板默认 3 次、14400 秒。正常 turn 结束、未交接且没有明确等待时，由平台在原会话追加一次继续指令；计数与对应完成消息持久化，事务检查当前 Run/seq/会话，重启和重复 tick 不重复排队。达到上限时留下明确等待原因，不宣称完成。失败、用户停止、权限撤销不自动续跑。等待后新用户输入沿用同一会话；轮数预算属于节点执行，不被每条消息重置。

这是执行器无关的平台生命周期检查，不把所有原生 Stop hook 或供应商都称为已支持。已有受信原生 hook 仍可执行，不继承任意基础 Agent 的本机命令。

## 安装与兼容

唯一维护源的正式模板/安装器设置新协议、角色与任务输入分离及有界持续推进。升级原 manifest 保留对象身份；旧 Run 的冻结定义、快照、原生会话不改；含退役Agent交接契约的历史Run可读取和停止，不再接续执行。保存的工作流通过正式API显式升级后，新Run使用新契约。新增节点使用新配置。开发实例升级前备份、核对无在途执行进程，重启后对旧 Run 逐项核对。不自动合并源 main。

## 节点生命周期补充契约

一轮结束是执行事件，不等于节点完成。沿用现有 running/waiting/completed/failed/stopped 状态及调度状态：正常交付以已接受的 handoff 为准；需要用户输入以已接受的等待工具为准；用户停止与执行失败分别按平台事实处理；没有交付或等待信号的正常收尾才有界接续。局部工具报错如已由 Agent 恢复，不直接等同整个执行失败。

节点 `allow_user_input` 为布尔开关，公开业务概念为“允许请求用户输入”，沿用一个 `wait_for_input(kind, reason)` 工具，不再新增同义的 need_user_input。新建节点与标准安装明确设置 true；已有 context_version1 定义缺失字段兼容原先开放行为，false 才显式关闭；context_version0 继续旧协议。开关按 Run 定义冻结。关闭时工具列表和服务端事务同时拒绝；生成的 SOP/继续消息不能要求使用未开放工具。需要澄清应交给已配置的合法目标，无信息且无出口时明确报告阻塞、保留现场，达到配置上限暂停，不编造答案、不创建新 Run 绕过限制。开关限制 Agent 主动请求，用户仍可主动补充或停止。

澄清需附可作答的具体问题/决定事项；blocked 说明真实外部条件，不能与用户问题混淆。等待记录绑定当前执行和运行中的输入消息。接受新用户输入原子清理等待；有排队/投递中的新输入时不接受旧等待。同一原生轮中已接受 steering 修正后，旧等待也不能盖回；该轮正常结束后沿原会话继续处理。跨节点只传已成功投递的 completed/steered 用户补充；明确丢弃、停止或投递结果不确定的输入保留审计，不被提升为新需求。

新协议每次调度 Claim 在同一事务轮换现有节点工具凭据，原进程的迟到请求不能提交到下一轮；不增加第二套执行身份。角色/项目规则/工具配置语义不变，仅执行凭据更新。当前 seq、停止状态、已保存结果及待处理用户消息继续由原事务检查。重复已接受结果只复用原结果，交接后等待 Agent 安静才推进。重启中断中的执行标记失败并提示检查副作用，不自动重放。

平台 Stop 检查不另调用模型判断意图，也不扫描问号或关键词。受信原生 Stop hook 在执行器进程内运行；平台只在整个 Executor 返回且 scheduler 已安静后检查。原生 hook 的内部接续不另入平台队列；完成信号优先，平台不能对同一次结束再排队。真实 Hook 协同记录见验证表。具体 Codex 行为参考[官方 Hooks 文档](https://learn.chatgpt.com/docs/hooks)，平台契约仍不依赖该执行器专有 Hook。

上限是暂停原因，不是完成或虚构的用户问题。页面根据 clarification/blocked/limit/disabled 分别显示原因与下一步。完成/交接仅证明生命周期出口被接受，交付质量继续由固定测试与独立 QA 负责。

## 取消与工作区占用

停止/失败仍可恢复且占用工作区。`POST /api/workflow-runs/{id}/cancel` 携带当前 seq，要求停止或失败且原生进程/Connector 已退出。取消在事务中关闭当前会话、停止未执行的排队输入、撤销节点工具凭据，并将 Run/当前步骤记为 cancelled；保留已接受结果、错误、历史消息和所有工作区文件。重复同 seq 取消幂等；过期 seq、跨用户或仍在执行均拒绝。取消后不能停止/恢复/回退，也不能通过旧会话或迟到工具恢复执行。

完成和取消释放工作区占用；其他 Run 状态继续占用同目录、父子目录及符号链接别名。取消不会撤销文件或外部副作用；新任务仍须符合 Connector 对干净 checkout 和正确仓库的验证，不能用取消绕过恢复检查。


## 执行节点的任务输入与参数引用

代码和项目命令从 `WORKFLOW_INPUT_FILE` 读取 JSON：`run_id`、`workspace_path`、`input`、`parameters`、`previous_results`。不把输入展开成 shell 命令。`parameters` 沿用现有字符串键值结构；节点结果中的 JSON 类型保持原样。

MCP 执行节点的 `arguments` 是固定参数；可选 `bindings` 按工具参数名引用任务输入或同一 Run 的前序结果。画布在「引用任务输入或节点结果」中编辑并保存此配置。例如：

```json
{
  "mode": "mcp",
  "server_id": "github",
  "tool": "create_issue",
  "arguments": {"title": "固定标题"},
  "bindings": {
    "title": {"path": "/input"},
    "body": {"node": "report", "path": "/result/inputs/report"}
  }
}
```

省略 `node` 时，路径从上述任务输入对象开始；指定 `node` 时，从该节点最近一次已结束的前序步骤对象开始（`node`、`seq`、`status`、`result`、`execution_receipt`、`error`）。节点使用已有画布 ID。循环或返工后只读取最新一次前序执行；最新一次缺值时不会回退到更早的结果，也不会使用固定参数兜底。

路径使用 JSON Pointer，支持对象字段和数组下标，`/` 与 `~` 分别写作 `~1`、`~0`。引用只替换对应顶层工具参数，不执行表达式、模板插值或读取宿主环境。路径缺失、未结束的前序步骤或参数不符合工具 Schema 时，在记录调用意图和发送外部请求之前失败。保存阶段校验引用格式、节点是否存在及工具契约；启动后用实际值校验完整 Schema。省略引用时沿用固定参数行为；不会修改已有冻结 Run。

最多 64 项引用；路径最多 2048 字节及 64 段；解析来源最多 8 MiB，最终工具参数最多 64000 字节。大材料用产物引用，不把完整报告塞进工具参数。平台连接、凭据、Agent home 等内部 Run 字段不属于引用来源；任务输入和节点结果仍须按项目规则脱敏。
