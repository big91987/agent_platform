# 工作流节点独立 Agent 配置

用户在工作流节点中配置角色、执行器、模型、Skill、工具、权限、原生设置，不必先创建共享 Agent。现有智能体仍用于独立会话；编排不提供复制智能体或模板入口。本次采用既有配置字段，不新增模板库、模板身份或同步机制。

节点新增 `agent` 配置，复用 Agent 的执行配置字段；节点名称、工作流授权与启用状态分别由节点/工作流负责，不接受配置中的 ID、授权用户或已解析工具。`agent_id` 仅用于旧定义兼容，两者互斥。旧定义编辑和标准升级时转为独立配置；旧 Run 的冻结图与已创建会话保持不变。新 Run 从节点冻结配置创建会话，不创建隐藏共享 Agent，也不依赖原共享对象的后续状态。

节点会话沿既有 workflow_steps 关联到 Run，agent_id 为空。会话与消息沿当前工作流授权和 Run 所有者校验；共享 Agent 会话保持旧权限。节点工具完成、等待、接续及人工恢复都遵循同一授权。可读的 Run 历史不等于允许撤权后继续执行。节点配置中的原生配置、环境、Skill 路径等管理信息不向普通用户的工作流/Run 响应泄漏；冻结输入检查保留原脱敏逻辑。

平台管理员保存节点配置时复用执行器配置、环境、Skill 与注册工具验证。工具连接在既有公共工具目录管理；节点保存选择和批准策略。运行图冻结节点参数；公共工具仍按执行时有效配置解析。UI 在节点右栏直接编辑全部字段，旧引用保存迁移时深拷贝原配置，保留旧协议说明与交接设置，不静默丢弃人工文本。

标准安装模板生成内嵌配置，不再为每个研发阶段创建共享 Agent。旧 manifest 升级保留工作流/Connector ID、旧共享 Agent 及冻结 Run，拒绝覆盖外部配置漂移；迁移配置写入同一工作流版本。旧 Agent 不自动删除或停用，以免影响历史或其他用途。

验收：无共享 Agent 新建并真实执行；旧配置迁移后修改源不影响节点/Run；工作流授权、撤权、跨用户输入和完成工具校验；普通响应不泄漏敏感配置；旧 agent_id 图继续工作；新安装及原 manifest 升级幂等；界面配置、保存重载与输入预览连续验证。

## 2026-10-07 配置一致性修订

当前设计取消新编排的独立 Session Prompt。角色是长期职责，任务经 User Input 进入；输入协议与兼容见[会话输入](workflow-session-input.md)。独立智能体和节点使用同一 `web/agent-config.js` 表单与读取/校验逻辑，名称在所属对象保存。独立智能体管理自身授权/启用，节点继承编排授权/启用。所有可编辑执行参数保存到同一组 Agent 字段。

卡片和详情显示名称、执行器及模型。执行器当前只支持 Codex；模型为空表示使用其默认模型。节点标题在编辑副本中修改，应用后更新画布，保存才写服务端；仅打开关闭不产生修改。画布铺满可用宽度，详情叠在右侧且独立滚动。

一次 Run 使用启动时指定的共享工作区，网页和 API 都写 `workspace_path`，之后不允许更换。Agent 的工作区模板只用于未指定现有工作区的独立会话；编排启动必需已有目录，因此新版节点不提供该字段，API 拒绝非空节点 seed_dir；旧冻结配置保持原样。没有通用工作流变量系统，任务数据通过 User Input、handoff 与工作区文件传递。

实施状态按[交付计划](../03-delivery/workflow-node-agent-plan.md)维护；本修订的真实浏览器、Codex 和产品研发链路验证完成前不沿用上阶段验收结论。

## 统一 Agent 交接（2026-10-22）

Agent 节点统一使用 MCP `handoff`；`target`、`message` 必填，`artifacts` 为可选工作区文件清单。单目标和结束节点都显式填写 target，工具枚举只接受已配置目标。固定字段含义由平台提供。

每个交接目标独立配置参数。节点的 `handoff_parameters` 以目标节点 ID 为键，值包含 `enabled`、`schema`（type=object）和 `instructions`；省略目标或 enabled=false 时不接受 params。开启的目标要求 params，工具完整 Schema 通过 target 分支约束参数，填写说明分别提供给 Agent；平台接受前再按实际 target 校验。关闭保留该目标的 Schema/说明，不向 Agent 提供其字段要求。参数可用于下游 Agent 或执行节点，不依据目标类型推断需求。节点级旧参数字段仅保留历史事实读取，新配置和新执行明确拒绝，正式升级需核对目标后显式迁移，不保留旧执行分支。类型化参数保存到 result.params，下游 Agent 在任务消息中读取；执行代码从 WORKFLOW_INPUT_FILE 的 previous_results 读取，MCP 显式引用 `/result/params/字段`。未配置参数引用时不自动推断、不拼接 Shell，缺值停止。

节点面板使用独立编辑副本；修改名称、配置、目标及规则都需点击“应用”后才更新工作流草稿和连线，顶部“保存”再持久化。取消放弃本次修改，关闭或切换节点有未应用内容时明确选择是否放弃；校验失败保持原字段供修正。代码/命令/MCP和结果来源分别保留编辑内容，execution_drafts 随正式配置持久保存 inactive 表单；只选定 execution 参与运行，隐藏草稿不参与权限、输出选择、调度或参数绑定。Schema/文件路径切回后恢复，不靠旧配置兼容分支。

原生回合结束且必要产物归档后才调度下一节点；待输入、权限、幂等、冲突和历史事实保留。

标准模板使用新契约；旧配置须经工作流 API 显式升级后才能新建 Run。旧 Run 冻结快照原样留存，不自动改写、转换或重放。以下记录保留作为已被替代的历史决策。

## 历史：交接模式与固定输出（2026-10-07，已被上节替代）

用户确认节点提供两种可切换的交接模式。新节点保存 `exit_mode=handoff|complete`，默认handoff；同一节点只启用一种方式。handoff页配置多个目标及各自选择策略；固定流转页配置唯一目标、`completion_schema`和`completion_instructions`。说明用于解释输出字段的来源、生成规则与示例，不另设任务说明。保留现有工具名complete_node。

固定工具保留summary与artifacts公共字段，Schema定义其inputs业务对象，支持JSON类型、嵌套对象与数组，未配置时沿用字符串键值对。自定义Schema在保存时检查有效性，工具注册时直接成为inputs参数Schema，并在持久化结果前按Run冻结定义再次验证。缺字段、类型或约束不符返回工具错误，Agent修正后重试；不落完成结果、不推进、不补造默认值。填写说明同时进入工具说明与输入预览。

输出直接存入既有result.inputs，命令Connector从标准stdin的previous_results读取同一对象及原类型，Agent下游通过既有输入组装得到其内容。无额外变量、字段映射层或输出对象ID。Schema首期使用本地支持的JSON Schema校验字段，不支持引用/自定义关键字；不远程加载schema、不执行表达式。配置说明最长16000字节，schema最长32000字节。

旧定义未设置exit_mode时继续按原边线执行，冻结Run不变。旧混合模式在编辑器明确选择新模式及保留目标，不能默默删线。标准模板升级为显式模式；混合协作示例改为统一handoff至校验或结束，不让新配置继续混用两个工具。模式切换到固定时若有多个目标，先选择唯一保留目标；切回handoff保留输出Schema草稿但不应用到handoff工具。开发分支直接提交推送，不创建Platform PR。

数值保真边界：在任何 MCP 参数重编码前检查 JSON 数值的十进制往返；无法无损表示的数值明确拒绝并要求字符串，不让验证库先舍入。Schema 字面量做同样检查。合法 `inputs:{}` 保留为空对象，不省略字段；未提供 inputs 的旧结果仍可省略。此约束也覆盖存储重载到命令 stdin 的路径。
